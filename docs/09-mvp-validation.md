# MVP 实现与验证记录

日期：2026-11-12；版本：0.1.0。此记录区分已经验证的结果与原始设计中的目标。

## 当前实现

Core 负责确定性计时；Windows 通过前台 Hook、1秒补偿采样、最后输入、WTS 会话、电源/显示状态获得事实；Storage 用 SQLite 事务和 revision 幂等更新保存；App 由独立工作队列协调小窗、详情和托盘。

存储实现为精简 schema v1，区间内嵌应用和 run/epoch 标识，使用 `daily_usage` 缓存、`store_state` 提交序号与 generation、设置和覆盖事件表。未为尚未实现的隐私规则/图标/升级迁移建立空功能表。原始文档04的独立 apps/tracking_runs/clock_epochs 等表是后续完整版本模型，不能直接视作当前数据库结构。

所有实时差值和提交确认在同一工作队列中处理：已提交日汇总 + 待写区间相对已提交版本的差值，成功读取新基准后才清除 pending。暂停优先在内存停止，设置写失败不会撤销暂停。存储失败会停止新计时并重试。

## 真实 Windows 运行

15秒采集验证中，初始显示状态从 `WaitingForDisplay` 转为可信状态，随后产生前台应用分段并保存；总有效与全部应用有效之和一致。修复输入时间采样顺序后，新运行的20个观察样本中除初始等待外没有 `InputUnknown`，有效/会话累计均为13,984毫秒，无采样缺口。

发现并修复的具体问题：先取得系统 tick 后再读取最后输入，遇到两次调用之间的新输入可能产生错误回绕。现改为读取输入后再取观察时间，并仅容忍32毫秒内的计时器量化差；较大异常仍拒绝。

自包含 EXE 的控制器验证结果：暂停前3,516毫秒，暂停等待后仍3,516毫秒；重新打开后仍3,516毫秒，未补算停止期间；恢复后增长到6,532毫秒。CSV导出成功，清空后记录为空且暂停偏好保留。该验证使用独立测试目录，与正式用户数据分离。

真实 WPF 小窗已启动并观察到今日累计、应用排行和当前前台应用；显示数据来自真实采集。未声称已完成所有按钮、多屏或缩放组合的GUI自动化。测试窗口通过专用参数展示于任务栏便于定位，正常模式小窗隐藏任务栏图标、通过托盘恢复。
