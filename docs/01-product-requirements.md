# ATime：产品需求文档

> 项目英文名：ATime；建议仓库名：`ATime`。本文件定义计划中的 MVP 行为，不代表功能已经实现。

## 1. 产品目标

面向 Windows 个人用户，持续统计当前电脑的使用时长和前台应用使用时长，并用一个可拖动的桌面小窗展示当天数据。用户应能随时回答三个问题：今天用了多久电脑、时间主要花在哪些软件、当前是否正在记录。

首版以统计口径清楚、记录可靠、查看方便为目标。数据保存在本机，不要求账号，不依赖服务器，不记录窗口标题、网页地址、键盘内容或屏幕内容。

## 2. 范围与默认决策

| 项目 | MVP 决策 |
| --- | --- |
| 支持平台 | Windows 11 x64；其他系统与 ARM64 留待兼容性验证后再承诺 |
| 用户与设备 | 一台电脑上的当前本地交互用户；不合并其他 Windows 用户的数据 |
| 远程场景 | RDP、远程控制和多会话并发不列入首版正确性承诺，受限状态需可见 |
| 桌面展示 | 常规无边框浮动窗口，可拖动、可隐藏、可切换置顶；不嵌入 Windows 桌面层 |
| 默认统计 | 「有效使用」，空闲阈值 5 分钟；用户已明确选择此默认口径 |
| 补充统计 | 「屏幕会话」，供阅读、视频等长时间无输入场景参考 |
| 数据 | 本地保存、CSV 导出、清空全部使用记录 |
| 隐私 | 可将指定应用的后续时长归入「隐私时段」，不保留应用关联明细 |
| 自启 | 默认关闭；用户可在设置中开启登录后启动 |
| 界面语言 | 简体中文；结构保留国际化空间 |

### 2.1 首版包含

- 识别当前前台应用，并根据会话状态累计两种口径的时长。
- 今日桌面小窗、系统托盘、今日 / 近 7 天 / 近 30 天详情页。
- 统计口径切换、暂停 / 恢复、置顶、位置记忆、主题设置。
- 空闲阈值设置、隐私应用规则、自启开关。
- 导出当前范围和当前口径的应用汇总 CSV，清空全部使用记录。
- 正确处理锁屏、显示器关闭、休眠、唤醒、跨日、程序异常退出及重新启动。

### 2.2 首版不包含

网站 / 标签页级统计、后台音乐时长、自动媒体播放识别、手动补时、应用分类、番茄钟、强制限额、云同步、账号、移动端、团队监控、键鼠内容采集和屏幕录像。系统启动之前或本工具退出期间的历史使用时长也无法追溯。

## 3. 两种统计口径

### 3.1 屏幕会话

在本工具正常运行、未暂停、存储健康、当前受支持的本地交互会话处于连接及解锁状态、系统报告显示状态为亮起或变暗且关键状态可信时累计。显示器关闭、锁屏、休眠及会话断开时不累计；变暗状态仍累计。远程会话与关键状态未知时停止累计，并显示相应原因。

它表示系统可观测到的可用屏幕会话时长，**不证明用户正在注视屏幕**。在多显示器和特殊硬件上，以系统提供的会话显示状态为依据，不承诺单独测量每一台显示器。状态不可可靠确认时，应标注统计受限，不将未知状态宣称为准确的亮屏测量。

### 3.2 有效使用

在满足屏幕会话条件的基础上，最近一次输入距当前时刻未达到空闲阈值时累计。默认阈值为 5 分钟，可以设置为 1、3、5、10 或 15 分钟。

规则采用「宽限时间计入、达到阈值后停止」：最后一次输入之后的前 5 分钟仍计入有效使用，超过阈值的部分只计入屏幕会话。恢复输入后继续累计有效使用，**不回扣前 5 分钟，也不将已判为空闲的时间补回**。

示例：10:00 最后一次输入，10:12 再次输入，期间屏幕始终亮起且未锁屏。10:00–10:05 同时计入有效使用和屏幕会话；10:05–10:12 只计入屏幕会话。阈值变更从变更时刻起生效，历史数据不重算。

阅读和看视频时，有效使用可能低于主观使用时长。用户可切换到屏幕会话查看相应时长；切换只改变展示和导出，不修改底层记录，也不停止另一种指标的采集。

### 3.3 前台归属及对账

同一个时刻仅归属一个应用桶。多窗口、多显示器、分屏和后台运行不会产生多份并行计时；谁拥有前台焦点，时长就归谁。一个应用的多个进程或窗口应按稳定应用身份合并；不能只依赖进程名称字符串。

对任意一个统计范围，必须成立：

```text
有效使用总时长 = 所有应用桶的有效使用时长之和
屏幕会话总时长 = 所有应用桶的屏幕会话时长之和
0 ≤ 有效使用总时长 ≤ 屏幕会话总时长
```

| 桶 | 处理规则 |
| --- | --- |
| 正常应用 | 以可识别的应用身份归属；浏览器统一计入浏览器应用 |
| 桌面与系统界面 | 用户停留于桌面、开始菜单等经可靠识别的系统界面时归入此桶 |
| ATime | 用户主动操作本工具详情或设置窗口时计入本工具 |
| 无法识别的应用 | 前台应用身份读取失败时保留时长，不擅自归给上一个应用 |
| 隐私时段 | 命中隐私规则时只保留匿名桶时长，不关联具体应用明细 |

小窗被动显示和刷新不得抢占焦点；用户点击小窗等导致本工具真正获得前台焦点时，按同一规则计入本工具。排除自身会导致总数与应用明细不一致，因此不做隐式排除。

暂停、退出和采集缺失属于未记录范围，不得归入「空闲」或隐私桶。界面应说明统计仅覆盖工具运行且允许记录的时段。

## 4. 核心用户流程

### 4.1 首次运行

1. 显示简短说明：本地保存、仅记录前台应用身份与时长、两种统计口径、默认 5 分钟空闲阈值。
2. 展示「开始统计」按钮，并提供「登录后自动启动」复选项，默认不选。
3. 用户开始后创建本地数据存储，固定统计时区为此时的系统 Windows 时区 ID，显示托盘图标和小窗。
4. 首次小窗位于当前主工作区的右侧中部，避开任务栏；首次出现「关闭小窗后仍在托盘记录」提示。

没有历史数据时从 0 开始，不推算用户当天此前的使用量。

### 4.2 日常查看

小窗持续显示今日总量、当前口径、记录状态、当前应用和排名前 3 的应用。点击「查看详情」打开详情页。详情可切换今日、近 7 天、近 30 天，并查看趋势及完整应用排行。

两种口径的切换须同步更新总量、趋势、排行、占比和导出范围描述，避免混用有效总量与会话明细。口径选择在小窗和详情间同步，并保存为下次启动的偏好。

### 4.3 暂停、隐藏与退出

| 操作 | 预期行为 |
| --- | --- |
| 暂停统计 | 立即停止两种时长累计；小窗和托盘显示「已暂停」 |
| 恢复统计 | 从恢复时刻起记录，不补回暂停期间 |
| 关闭小窗 | 仅隐藏小窗，继续统计；可通过托盘恢复 |
| 关闭详情页 | 仅隐藏详情视图，不改变统计状态 |
| 退出程序 | 落盘后退出全部进程，停止记录 |
| 重新启动 | 默认恢复正常记录；若上次处于用户主动暂停，则保留暂停状态 |

暂停状态持久化，避免用户重启后意外恢复记录。应用异常退出后的重启不补计中间缺口。自启与上次是否显示小窗分别保存：用户隐藏小窗后，下次启动仍可仅显示托盘。

### 4.4 隐私应用

设置中使用「将应用加入隐私时段」而非容易产生歧义的「不统计此应用」。用户从已识别应用列表选择，或通过文件选择器添加可执行文件；添加后清楚提示「后续时长仍计入总计，但不显示具体应用」。

- 新规则仅影响之后的采集，不自动删除、重写或隐藏历史明细。
- 命中规则后，持久化时长只关联隐私桶，不写入具体应用关联明细；当前应用区域也显示「隐私时段」。
- 规则列表自身需要保存匹配所需的应用标识，设置页应说明这一点。
- 删除规则只恢复未来的应用识别，已匿名记录不还原。
- 隐私应用仍在前台时，也遵守空闲、锁屏、暂停及显示状态规则。
- 应用列表中的过滤、排序、折叠仅改变视图；它们不等于隐私处理或删除数据。

### 4.5 导出与清除

导出对象为当前统计范围下的「逐日 × 应用桶」汇总数据，以当前口径标记所选指标及对应秒数，同时保留有效与会话秒数两列方便对账。导出对话框明确展示起止日期、所选指标、统计时区和保存位置；不导出窗口标题、网址、完整可执行路径或输入信息。隐私时段仅显示匿名桶。导出使用一致的已提交快照；若当前缓冲保存失败，须说明最后成功保存时间，由用户决定是否导出截至该时刻的数据。

清除入口明确命名为「清空全部使用记录」，执行前二次确认。确认后清空使用明细、聚合、覆盖与运行记录、相关使用历史缓存和程序管理的历史备份，刷新小窗与详情；保留外观、自启、统计时区与隐私规则等设置。清除不改变用户主动暂停的选择：清除前已暂停，完成后仍暂停；此前允许记录，则重新检查所有计时条件，从新的可靠基线开始累计。用户已自行导出的 CSV 不在清除范围内。清空不承诺存储介质级安全擦除。

## 5. 时间范围与展示

| 范围 | 定义 |
| --- | --- |
| 今日 | 固定统计时区下，当天 00:00 到当前时刻 |
| 近 7 天 | 今日与此前 6 个自然日，包含尚未结束的今日 |
| 近 30 天 | 今日与此前 29 个自然日，包含尚未结束的今日 |

跨午夜的时长应按真实边界拆分。首次启动固定统计时区后，系统时区变化不重分历史日期；MVP 设置页展示该时区，只读。夏令时切换按该时区的真实日界处理，不能假定每个自然日都是 24 小时。

内部保存高精度时长；主界面用小时、分钟显示，悬停或详情可查看更精确数值。总数由原始时长求和后格式化，不由已经取整的行文本相加。若显示精度造成逐行相加与总数有一分钟差异，需用提示说明；占比同理。

## 6. 非功能需求

以下是开发验收目标，不是已经测得的性能结果：

| 类别 | 目标 |
| --- | --- |
| 响应 | 常规本地操作在 200 ms 内给出界面反馈；数据读取较慢时显示加载状态 |
| 实时性 | 正常运行时小窗和详情总量约每秒刷新；不频繁重排排行导致难以阅读 |
| 轻量 | 在 Windows 11 x64 参考设备上常驻空闲平均 CPU 目标 < 1%，内存目标 < 150 MB；以实际基线和测量方法验收 |
| 安全运行 | 普通用户权限，不要求管理员启动，不注入其他进程 |
| 本地性 | 首版正常统计无需联网；不发送使用记录或诊断日志 |
| 可恢复 | 异常退出后数据库可打开；不重复累计已提交时段、不补记退出缺口 |
| 可诊断 | 采集受限、存储失败等情况可见；诊断日志不写窗口标题、网址或输入内容 |
| 可访问 | 键盘可操作，按钮有可访问名称，主要状态同时用文字和图形表达 |

具体采样误差、持久化间隔和故障恢复预算由技术设计与测试计划约束。不能仅凭 UI 演示通过性能或正确性验收。

## 8. 产品边界与文案约束

「有效使用」是基于输入活动的估算；「屏幕会话」是基于 Windows 会话及显示状态的统计。两者都不能准确判断注意力或工作效率，因此界面不展示未经定义的「生产力评分」。

不把未知应用、未运行缺口、暂停、锁屏和空闲混成一个「其他」原始分类。「其他」只能作为小窗展示时对剩余应用的折叠，详情与导出仍需可对账。

统计受限须说明影响范围和恢复操作。数据为空、未记录和真实的零时长使用不同文案，不用随机样例填充正式数据视图。
