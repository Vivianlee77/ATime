# 测试与验收计划

版本：v0.1；日期：2026-11-12。以下是待实现软件的测试设计，**不表示真实采集器已经通过测试**。

## 1. 验收方法

计时内核使用注入时钟和事件重放，做到预期结果确定；数据库使用隔离临时目录做事务与崩溃测试；真实 Windows 机器验证系统事件、焦点、权限、显示器及运行性能。三层都通过才可认为 MVP 完成。

所有数字先以原始毫秒核对，再检查显示格式。每份验收记录注明程序版本、Git commit、OS/build、CPU、内存、显示器与 DPI、时区、测试步骤、结果和异常证据。正式样本不使用用户敏感内容。

## 2. 确定性计时用例

下表假设程序正常运行、当前本地会话已连接、显示开启、时区 UTC+8、阈值 300 秒；未特别说明时输入足够频繁。每例使用独立时间轴。

| ID | 输入事件 | 有效 E | 会话 S | 必须验证 |
| --- | --- | --- | --- | --- |
| CT-01 | A前台120s，B前台60s | 180s | 180s | A120/B60，后台A不重复计 |
| CT-02 | t=0最后输入，屏幕保持12min，无后续输入 | 300s | 720s | 阈值后的420s仅是会话；不回扣 |
| CT-03 | 承接CT-02，t=720输入并继续用30s | 330s | 750s | 只从新输入继续，不补中间420s |
| CT-04 | 用60s，锁屏600s，再用60s | 120s | 120s | 解锁重读状态，锁屏不计 |
| CT-05 | 用60s，显示off120s，再on用60s | 120s | 120s | off不计；另将off改dim时会话应240s |
| CT-06 | 用60s，手动暂停120s，再恢复60s | 120s | 120s | 暂停不是空闲；暂停期间无应用区间 |
| CT-07 | A正常60s，开启A隐私规则，A再用60s | 120s | 120s | A60/private60；后一段无A关联 |
| CT-08 | 正常30s，未知应用30s，自己界面30s | 90s | 90s | 每个桶30s，不沿用旧应用 |
| CT-09 | 23:58到次日00:03持续活跃 | 300s | 300s | 前日120s，次日180s；汇总/图表同分割 |
| CT-10 | 连续用120s，中途系统UTC向前调1h | 120s | 120s | 无增加3600s，epoch变化并有质量标记 |
| CT-11 | 连续用120s，中途UTC回拨1h | 120s | 120s | 不负数、不重复累计，旧新epoch区间有序 |
| CT-12 | 已确认t=0..10；下一可信样本t=20，中间无事件 | 10s | 10s | [10,20)为缺口；t=20后重新开始 |
| CT-13 | 正常10s后睡眠1h，恢复正常10s | 20s | 20s | 有/无提前suspend通知两种路径；不算睡眠 |
| CT-14 | 同一前台/锁定事件重复投递；旧事件晚到 | 与去重基准一致 | 与去重基准一致 | 无零长度永久段、无倒退；晚到需重采样 |
| CT-15 | 最近输入tick跨32位回绕，实际间隔2s | 按实际2s | 按实际2s | 不生成巨大空闲/有效时间；异常tick另走受限 |
| CT-16 | 最后输入后4min，将阈值5min改为2min，再过1min | 240s | 300s | 设置变更后立刻空闲，历史240s保留 |
| CT-17 | 暂停后锁屏/解锁/重启 | 不新增 | 不新增 | 用户暂停优先保留，用户恢复才记录 |
| CT-18 | 连接变成远程会话，稍后返回本地 | 仅本地可信部分 | 仅本地可信部分 | 远程状态可见，回本地重采样 |

CT-12 的“已确认t=0..10”指此前1秒采样连续，非只有t=0、10两个样本。CT-05 的dim版本要保证输入足够频繁，有效才也为240s。

补充属性测试：任意事件序列始终 `0 ≤ E ≤ S`、各桶和等于总数、同一 run 单调区间不重叠、duration非负；重放相同序列得到相同结果。注入不规则采样间隔验证使用真实时间差，不按tick数量累加。

## 3. 存储与恢复

| ID | 场景 | 验收标准 |
| --- | --- | --- |
| DB-01 | 同一段5s检查点重复提交3次 | 只计5s，revision不回退 |
| DB-02 | 同一段由5s更新为10s，随后重试5s，再同终点封口 | 最终10s，汇总与原段一致；封口版本递增且被保存 |
| DB-03 | 原始段更新后、汇总更新前触发失败 | 事务全部回滚；不存在单边更新 |
| DB-04 | 内存段10s、库里已存5s，随后收到提交确认；交错旧查询返回 | UI始终10s；旧commit结果不覆盖新快照，封口未确认段不丢失 |
| DB-05 | 正常写入状态下多次随机强杀进程再启动 | 无损坏/重算；丢失已观察尾段目标≤5s，旧段不延长到重启 |
| DB-06 | 模拟磁盘满、只读、锁竞争 | 记录保存失败可见；不以记录中继续涨数；恢复不补不可确认区间 |
| DB-07 | 对比按段重新聚合与daily缓存 | 任意日期/应用的两个指标完全相等 |
| DB-08 | 迁移失败、恢复备份、旧程序读新schema | 旧数据可恢复；旧程序拒绝写新schema |
| DB-09 | 写入期间在线备份再打开备份 | 备份一致且可查询；不直接复制活跃db漏掉WAL |
| DB-10 | 清空历史与写入/导出并发 | 操作先协调队列；旧generation结果无效；备份/缓存同步清除，主动暂停保留 |
| DB-11 | 原生SQLite版本/完整性检查 | 实际库包含WAL修复；受控中止恢复后完整性检查通过 |
| DB-12 | 当前统计日跨整点、跨午夜、DST变化 | 日/小时分桶正确；重复小时能区分，不假定24h |

故障注入仅作用于隔离测试库。不能用开发者真实使用记录做破坏性测试。

## 4. 真实 Windows 场景

| 组 | 检查内容 |
| --- | --- |
| 前台应用 | VS Code、Edge/Chrome、Windows Terminal、文件资源管理器、设置、一个打包应用；快速Alt+Tab、多个同应用窗口、前台进程立即退出 |
| 权限与身份 | 普通权限运行；访问受限/管理员应用、PID复用、空HWND、ApplicationFrameHost、路径变化；未知归属不崩溃 |
| 系统状态 | 锁屏/解锁、睡眠/休眠、显示off/on/dim、用户快速切换、拔电源；状态通知连发或遗漏时不误补 |
| 初始状态 | 首次登录启动、仅托盘启动、恢复后启动；尚未得到可靠状态时不直接假定全开 |
| 窗口 | 隐藏、恢复、拖动、置顶开关、长名称；被动刷新不抢焦点；只退出操作关闭进程 |
| 显示器 | 单屏/双屏、负坐标工作区、主屏切换、拔掉小窗所在屏、100/125/150/200% DPI |
| 用户与实例 | 同用户重复启动；另一用户独立数据；同用户第二会话不得并发写；RDP明确受限 |
| 输入模式 | 长时间阅读/视频、后台音乐、触摸/触控板；游戏手柄及远程注入输入不做未经验证的有效性承诺 |
| 日历 | 固定统计时区与系统时区不一致、跨午夜、调整系统时间、DST前进/后退的受控测试环境 |
| 自启与安装 | 自启默认关，开关后实际注册一致；带空格路径；升级后启动项有效，卸载可清理 |

在支持列表内至少验证两种 Windows 11 版本/配置，包括笔记本和台式机或等效多屏环境。不能从一个虚拟机推导所有真实硬件状态。

## 5. 误差与性能预算

以下为目标，发布前实测并记录环境；不满足时优化或如实调整支持范围。

| 项目 | 方法 | 目标 |
| --- | --- | --- |
| 事件边界 | 实际应用切换并与参考时间戳对照 | 正常事件路径P95≤1s；补偿采样发现遗漏目标≤2s，不宣称硬实时 |
| 单应用连续时长 | 10min、持续输入、无故障 | 总误差≤2s；系统负载/缺口另计并显示 |
| 纯计时内核 | 注入毫秒级事件 | 与确定预期完全一致，无显示取整影响 |
| 常驻CPU | 4核以上、8GB内存、SSD参考机器；预热2min后采20min，关闭详情 | 平均<整机总CPU的1%；按进程CPU时间/(墙钟×逻辑核数)归一化 |
| 常驻内存 | 同上，小窗显示；记录Private Bytes | 稳态目标<150MiB；打开详情峰值目标<250MiB |
| 本地交互 | 计时与采集持续运行 | 暂停/恢复/切换口径200ms内有反馈，耗时查询显示加载 |
| 数据查询 | 合成100万段、30日范围 | 参考机P95<300ms，UI不阻塞 |
| 可靠性 | 24h持续运行，含8h使用与锁屏/休眠循环 | 无崩溃/重复累计；预热后内存不持续线性增长 |
| 磁盘行为 | 观察写频率和WAL体积 | 正常5s检查点，状态变化可提前；无每秒永久插行或失控WAL增长 |

手动秒表只能用来做粗验收；精确边界用可重复信号和受控测试窗口记录参考时间。不要为了看起来精确而隐藏未采样缺口。

## 6. 隐私、导出与无障碍

- 抓取进程网络行为验证正常记录不向网络发送数据；打开用户主动选择的外部链接单独标识。
- 检查数据库、WAL、日志、缓存和CSV：无窗口标题/网址/输入内容；私密应用时段只关联private桶。规则列表可包含匹配身份，但不得关联时间流水。
- CSV核对中文编码、逗号/引号/换行、公式触发前缀、原始秒数、全部桶和统计时区；先提交再生成一致快照。
- 清空后按范围查询为空，设置与暂停偏好保留，当前旧段不能复活；用户外部CSV不删除。
- 键盘完成口径切换、暂停、开设置、导出、关闭、退出；焦点可见，屏幕阅读器能读按钮和状态。
- 深浅主题的实际色值检查对比度；高DPI和文字放大不截断时长/关键操作；柱图有文字等价信息。

## 7. MVP 发布门槛

1. PR-01–18、CT-01–18、DB-01–12全部通过；无法在CI自动化的项目有真实机器证据。
2. E/S总量与应用桶、日汇总、图表、CSV一致；没有已知重复累计、休眠补算或隐私明细泄漏问题。
3. 小窗/托盘稳定恢复，安装/升级/自启/卸载在普通用户下验证。
4. 24h稳定性及性能预算完成实测，失败项已修复或明确减少首版承诺，不把目标写成测量结果。
5. README、数据位置、统计规则、使用限制、版本与发行校验值齐全；发布包在未装开发SDK的干净机器可运行。
6. 作者完成一轮真实日常试用，能解释“有效”和“会话”的差异，能暂停、恢复、找回小窗、导出和清空数据。
