# ATime：界面与交互设计

> 本文件是交付给开发的界面规格。尺寸单位为 DIP；最终字体、系统控件和高 DPI 效果需在真实 Windows 环境验证。

配套 HTML 原型只演示浅色主题下的部分主流程，用于确认视觉方向与主要交互，不包含本文件的全部正式功能和异常状态。开发范围以产品需求、技术设计和本文件为准。

## 1. 设计原则

界面首先展示时长，其次说明当前口径和记录状态。日常查看只需小窗；详细分析放入详情页；采集参数和隐私管理放入设置。对暂停、退出、隐藏和清除使用不同文案，避免用户误判是否仍在记录。

整体采用清晰留白、柔和圆角、低对比边框和单一强调色。数字采用等宽数字特性，刷新时不左右跳动。首版主题提供跟随系统、浅色和深色，默认跟随系统。

## 3. 桌面小窗

### 3.1 尺寸与位置

默认外框为 280 × 360 DIP，主要内容内边距 16 DIP，圆角建议 12 DIP。该高度为总时长、状态、前三应用和操作保留可读空间。窗口尺寸先固定，避免首版引入复杂自适应布局；系统文字放大时允许扩展高度，不得截断关键状态和操作。后续可增加只显示总数的紧凑模式。

首开出现在主工作区右侧中部，距右边缘约 24 DIP，避开任务栏。顶部非按钮区域可拖动；记忆上次位置和所在显示器。显示器断开、缩放变化或窗口完全落在可见区域外时，将其恢复至当前主工作区。坐标按设备与 DPI 转换处理，不能把历史像素坐标直接当成当前 DIP。

默认开启置顶，允许关闭；不自动获取焦点、不随秒级刷新唤醒窗口。置顶意味着可能覆盖其他窗口，悬停置顶按钮时明确显示当前状态。首版不提供点击穿透，以免窗口进入难以恢复操作的状态。

### 3.2 内容布局

```text
┌────────────────────────────────┐
│ ATime               [钉] [×]│  标题 / 拖动区
│ 今日 · 有效使用           [▾]  │  可切换指标
│ 4 小时 26 分钟                 │  主数值
│ ● 正在记录 · Visual Studio Code│  状态 / 当前应用
│                                │
│ VS Code     ━━━━━━━━━   1时48分 │
│ Edge        ━━━━━       1时12分 │
│ Terminal    ━━━          46分  │
│ 其他 40 分钟                   │
│ [暂停]               查看详情 →│
└────────────────────────────────┘
```

示意数据仅用于原型。上述有效使用 4 小时 26 分钟由 108 + 72 + 46 + 40 分钟组成。切到屏幕会话时，示例总量为 6 小时 2 分钟，由 VS Code 130、Edge 120、Terminal 55 和其他 57 分钟组成。「其他」是剩余应用桶的展示折叠，不是存储类别。当前应用名使用省略号和悬停完整名称，不能挤占主时长或状态操作。

小窗不放日期选择器；它固定展示今日。口径切换菜单仅包含「有效使用」和「屏幕会话」，每项附一行解释。当前指标名称始终可见。

### 3.3 状态呈现

| 状态 | 文字与动作 | 计数展示 |
| --- | --- | --- |
| 正常有效记录 | 绿色点 +「正在记录 · 应用名」 | 两指标按各自规则累计 |
| 超过空闲阈值 | 中性点 +「空闲中 · 有效使用暂停」 | 有效值不增加；切到会话时会话值继续增加 |
| 选择会话且当前空闲 | 中性点 +「会话记录中 · 当前无输入」 | 会话值继续增加，避免写成全局暂停 |
| 用户暂停 | 暂停图标 +「已暂停记录」；主按钮变为「恢复」 | 两种值均冻结 |
| 隐私应用前台 | 「正在记录 · 隐私时段」或对应空闲状态 | 不显示真实应用名、图标或路径 |
| 前台身份未知 | 「正在记录 · 无法识别的应用」 | 归入未知桶，不自动暂停全部记录 |
| 统计受限 | 提示图标 +「部分统计受限」；点击查看原因 | 不把受限状态伪装为正常精确统计 |
| 数据写入失败 | 错误图标 +「记录保存失败」；点击查看恢复说明 | 不用绿色正常状态掩盖失败 |

锁屏及休眠期间用户通常看不到小窗；恢复后从最新确认状态显示，不播放漏掉期间的数字增长动画。小窗刷新约每秒一次；排行最多每 5 秒重排一次，避免两个应用数值相近时频繁跳动。

### 3.4 关闭与托盘

「×」的可访问名称与悬停提示为「隐藏小窗，继续记录」。首次隐藏时展示一次非阻塞提示：「仍在托盘记录，右键托盘图标可退出」。以后不重复打扰。

托盘图标的悬停文本显示「ATime｜今日有效使用 4 小时 26 分钟｜正在记录」或等价的当前口径与状态。单击显示小窗，双击行为不额外触发第二个窗口；右键打开菜单。暂停状态通过图标形态和文字共同表达，不能只改变颜色。

## 4. 统计详情页

### 4.1 窗口结构

默认尺寸建议 1000 × 720 DIP，最小尺寸建议 800 × 600 DIP，可调整大小。顶部为产品名称与设置入口，其下依次为查询控制、总量概览、趋势、应用排行。主要内容可垂直滚动，不要求小屏设备同时显示全部内容。

```text
┌────────────────────────────────────────────────────────┐
│ ATime · 统计                                   设置 │
│ [今日] [近7天] [近30天]  有效使用 ▾          导出 CSV │
│ 2026-11-12 · 统计时区：中国标准时间                    │
│                                                        │
│ 总时长                最常用应用         记录状态     │
│ 4 小时 26 分钟        VS Code            正在记录     │
│                                                        │
│ 使用趋势                                               │
│ [今日：小时分布；7天/30天：逐日分布]                    │
│                                                        │
│ 应用                       时长             占比       │
│ VS Code                    1时48分           40.6%      │
│ Edge                       1时12分           27.1%      │
│ Terminal                   46分             17.3%      │
│ 桌面与系统界面             20分              7.5%      │
│ ATime                   12分              4.5%      │
│ 无法识别的应用             8分               3.0%      │
└────────────────────────────────────────────────────────┘
```

日期仅为原型示意。正式运行时取固定统计时区对应的查询日期。状态卡表示此刻的采集状态；历史范围内的总时长仍只反映该范围，不可用当前状态暗示整段历史都完整覆盖。

### 4.2 查询控件

- 日期范围与指标共同构成一次查询；切换时成组更新总量、图表、排行和导出描述。
- 近 7 天明确写「含今日」；近 30 天同理。标题同时显示实际起止日期。
- 加载中保留布局，显示加载状态；避免旧总数和新排行同时出现。
- 无数据时总量显示 0，图表显示空状态，并说明「此范围内没有使用记录」；不显示演示数据。
- 当前口径下某应用为 0 时默认不显示该行；若用户切换指标导致行变化，属于正常结果。

### 4.3 趋势图

今日按统计时区的小时分布显示柱形图；近 7 天和近 30 天按自然日显示。每张图只呈现当前指标，不用未标注的双轴。悬停与键盘焦点均可显示时间区间、精确时长及口径。

没有记录的时段与已记录但当前指标为零的时段，不应在提示文案中混为「未使用电脑」。跨夏令时的重复小时使用带 UTC 偏移的标签区分；缺失小时不虚构时段。首版不以图表推算未被采集的历史。

### 4.4 应用排行

默认按当前指标时长降序；相同时按稳定应用显示名排序，保证刷新稳定。每行包含图标、应用名、时长、占比和轻量进度条。进度条以该范围总时长为分母；占比不因隐藏搜索结果而重算。

桌面与系统界面、无法识别的应用、隐私时段与普通应用一起参与对账。未知桶旁提供解释：「部分前台应用无法读取身份，时长仍保留」。隐私桶提示：「这些时段已隐藏应用身份」。

不显示完整可执行路径，避免无意暴露用户名或目录结构。需要区分同名应用时使用来源、发布者或由解析器提供的稳定区分标签；只有在设置中确有匹配需要时才展示必要标识。

## 5. 设置页

### 5.1 常规与小窗

| 控件 | 默认值 | 交互 |
| --- | --- | --- |
| 登录后自动启动 | 关闭 | 即时保存；失败时回滚开关并说明原因 |
| 小窗置顶 | 开启 | 与小窗钉住按钮同步 |
| 主题 | 跟随系统 | 可选跟随系统 / 浅色 / 深色，立即生效 |
| 恢复小窗位置 | 按钮 | 将小窗放回当前主工作区的可见位置 |

不将「关闭小窗」或「隐藏到托盘」设计成退出。设置页提供说明：「退出程序后不记录，之后也不能补回这段时间」。

### 5.2 统计

空闲阈值使用下拉框，可选 1、3、5、10、15 分钟。用户已明确选择默认「有效使用 + 5 分钟空闲阈值」。旁边固定说明：「达到阈值后停止累计有效使用；前面的宽限时间保留。修改只影响之后的记录」。

统计时区以只读信息显示，说明首次启动时确定，系统时区变化不重排历史。显示两种指标的定义，并提供阅读 / 视频场景提示：「长时间没有键鼠输入时，可查看屏幕会话」。不设计暗示能够自动识别人是否在观看的开关。

### 5.3 隐私应用

顶部说明：「指定应用的后续时长进入隐私时段，总时长仍保留。匹配规则本身会保存应用标识」。下方显示规则列表与「添加应用」。列表行显示应用名称、必要的匹配来源和「移除规则」。

添加流程：选择已识别应用或可执行文件 → 展示将匹配的应用身份 → 确认添加。成功提示必须包含「仅对之后的记录生效；已有记录不变」。原有历史删除在数据管理中处理，不与添加隐私规则捆绑执行。

移除规则的说明为「恢复记录此应用之后的使用情况；已有隐私时段不会还原」。当前前台命中隐私规则时，小窗、托盘和详情实时状态都不能泄露该应用名称或图标。

### 5.4 数据管理与关于

显示数据保存位置、已记录日期范围、应用版本、当前采集状态和故障诊断入口。诊断内容仅包含必要错误码与运行信息；正式日志中不记录窗口标题或网页地址。

「清空全部使用记录」采用危险操作样式，放在独立区域。确认框示例：

> 清空全部使用记录？
>
> 将删除本机历史使用记录及本工具管理的历史备份。外观、自启和隐私规则将保留；已导出的 CSV 不会删除。当前的暂停选择保持不变；正在记录时，会在清空完成并确认系统状态后重新计时。
>
> [取消] [清空记录]

清除过程中禁用重复提交；结束后统一刷新小窗、详情、查询缓存及图表。清除前为用户主动暂停的，完成后仍显示「已暂停记录」，不能自动恢复。失败时保留明确错误状态，不显示已成功清除。

## 6. 导出交互

点击「导出 CSV」后先显示一行确认摘要，例如「2026-11-06 至 2026-11-12 · 有效使用 · 中国标准时间 · 逐日应用汇总」，随后选择本地保存位置。文件名建议包含范围与所选口径；CSV 同时保留两种时长列，并用所选指标列对应当前视图。导出前请求提交当前缓冲，失败时显示最后保存时间，允许用户取消或明确选择导出截至该时刻的数据。

导出完成显示可打开所在文件夹的成功提示。取消保存不报错；文件被占用、权限不足、磁盘空间不足时，保留当前查询条件并给出重新选择位置的操作。为方便 Excel 打开，CSV 采用 UTF-8 BOM，名称字段须正确转义并防止被解释为公式；具体列定义见数据设计。

## 7. 空状态、错误与覆盖说明

| 场景 | 文案与行动 |
| --- | --- |
| 尚未开始 | 「从现在开始了解你的电脑使用时间」 + 开始统计 |
| 今天无记录 | 「今天还没有使用记录」 + 当前状态说明；暂停时提供恢复 |
| 工具中途才启动 | 「统计仅覆盖本工具运行且允许记录的时段」；不称为完整全天数据 |
| 无法识别应用 | 「部分时段无法读取应用身份，已归入无法识别的应用」 |
| 受限或不支持会话 | 「当前会话的部分统计不可用」 + 具体原因；不展示未经支持的准确性承诺 |
| 数据库不可写 | 「使用记录暂时无法保存」 + 重试 / 查看保存位置；保留状态可见 |
| CSV 失败 | 「导出失败」 + 具体原因和重新选择位置 |

状态反馈遵循技术状态机的优先级：保存失败、用户暂停、会话不支持 / 断开、锁定、挂起 / 显示关闭、关键状态未知、空闲、正常记录。若存在多个问题，主状态显示上述最高优先级项，详情可展开其余问题。恢复系统状态或完成数据清除不会覆盖用户主动暂停。

## 8. 视觉及可访问性规格

| 元素 | 建议规格 |
| --- | --- |
| 主字体 | Windows 系统 UI 字体；中文使用系统中文回退字体 |
| 小窗主数字 | 28–32 DIP，半粗体，等宽数字 |
| 常规正文 | 13–14 DIP；关键状态不低于 12 DIP |
| 强调色 | 蓝绿色或蓝色，兼容浅 / 深主题；不同时引入多套饱和色 |
| 状态 | 图标 + 文字；颜色仅作为补充 |
| 焦点 | 清晰可见的键盘焦点框，按视觉顺序移动 |
| 控件 | 图标按钮有悬停文案及 UI Automation 名称 |
| 动效 | 短淡入和轻微状态过渡；尊重系统减少动画设置 |

主要文本与背景对比度以至少 4.5:1 为设计目标，较大文本至少 3:1；这些值需在最终主题颜色确定后实测。100%、125%、150%、200% 显示缩放及系统文本放大都要验证，不能只检查浏览器原型。

## 9. UI 验收重点

1. 280 × 360 DIP 默认小窗能显示总时长、指标、状态、前三应用和主要操作；长应用名不会撑破布局。
2. 显示与隐藏小窗、刷新数字不会自动改变当前前台应用。
3. 口径切换后所有可见统计一致，CSV 导出说明与当前查询一致。
4. 暂停状态、空闲状态、隐私应用状态、采集异常状态均有独立可理解文案。
5. 小窗隐藏后能通过托盘恢复；多次操作不会创建重复采集实例或重复窗口。
6. 多显示器拔插和 DPI 变化后，小窗不会永久落在屏幕外。
7. 只有键盘的用户可以打开详情、切换口径、暂停、导出、进入设置及退出。
8. 演示数据只出现在原型，正式空数据界面不使用占位数值伪装真实记录。
9. 清除、导出、自启设置失败时均显示失败原因，控件状态不冒充成功。
10. 使用记录的精度解释、空闲阈值解释与隐私规则生效范围，在对应操作附近可找到。
